Building from source

QtDMM needs a C++17 compiler, CMake ≥ 3.16, Qt 6 with the SerialPort, Charts and Linguist tools modules, and hidapi for USB‑HID cables. Qt Bluetooth (Connectivity) is optional — without it the program is built without the Bluetooth LE port. Install the packages for your system — the lists below are what the CI builds use; package names can differ between distributions and releases, so if one is not found, search your package manager for the Qt 6 module (serialport, charts, connectivity, tools) and for hidapi. Then the steps are the same everywhere:

git clone https://github.com/tuxmaster/QtDMM.git
cd QtDMM
cmake -S . -B build -DCMAKE_BUILD_TYPE=Release
cmake --build build --parallel
./build/qtdmm                       # run it
ctest --test-dir build              # optional: run the test suite
sudo cmake --install build          # optional: install system‑wide

On Linux and FreeBSD ./compile.sh wraps the same steps (compile.sh run, ctest, install, pack for a .deb and source tarball, appimage, doxygen).

Debian, Ubuntu and derivatives

sudo apt install build-essential cmake ninja-build git \
    qt6-base-dev qt6-tools-dev qt6-tools-dev-tools \
    qt6-serialport-dev qt6-charts-dev qt6-connectivity-dev \
    libhidapi-dev

Ubuntu 22.04 ships Qt 6.2, which is enough; 24.04 and Debian 12 or later have everything in the main repositories.

Fedora and other RPM‑based systems

sudo dnf install gcc-c++ cmake ninja-build git \
    qt6-qtbase-devel qt6-qttools-devel \
    qt6-qtserialport-devel qt6-qtcharts-devel qt6-qtconnectivity-devel \
    hidapi-devel

openSUSE uses the same package names with zypper; on RHEL/Rocky/Alma the Qt 6 modules come from EPEL.

FreeBSD

pkg install cmake ninja pkgconf git \
    qt6-base qt6-serialport qt6-charts qt6-connectivity qt6-tools hidapi

Serial ports are /dev/cuaU0 and so on; USB‑HID cables appear as /dev/uhid devices, which hidapi opens directly.

Arch Linux and macOS

Arch: sudo pacman -S cmake ninja qt6-base qt6-tools qt6-serialport qt6-charts qt6-connectivity hidapi, or build the package with the PKGBUILD in the repository. macOS: brew install cmake ninja qt hidapi; Homebrew's qt contains all modules, so the same three CMake lines produce build/qtdmm.app.

Windows

This is how the CI builds the installer; it uses Visual Studio 2022 (the free Build Tools are enough — select the Desktop development with C++ workload) and Qt from the Qt online installer. In the installer pick a Qt 6.8 release with the MSVC 2022 64‑bit kit and the additional modules Qt Serial Port, Qt Charts and Qt Connectivity. hidapi is fetched and compiled by CMake automatically. Then, in an x64 Native Tools Command Prompt for VS 2022:

git clone https://github.com/tuxmaster/QtDMM.git
cd QtDMM
cmake -S . -B build -G Ninja -DCMAKE_BUILD_TYPE=Release ^
    -DCMAKE_PREFIX_PATH=C:\Qt\6.8.3\msvc2022_64
cmake --build build
cmake --install build --prefix dist      # dist\qtdmm.exe plus the Qt DLLs (windeployqt runs automatically)

Adjust the Qt path to the version you installed. cpack --config build\CPackConfig.cmake produces the portable ZIP and, with Inno Setup installed, the installer — exactly what the GitHub workflow publishes, so if you just want to run a current build, take its artifact instead.

After the build

On Linux, add yourself to the group that owns the serial port (dialout on Debian/Ubuntu/Fedora, uucp on Arch) and log in again; QtDMM names the group if it cannot open a port. Bench meters through sigrok need sigrok-cli installed separately — see the download page. The API documentation is built with cmake --build build --target doxygen when Doxygen (and optionally Graphviz) is installed.

Contributing

Development happens on github.com/tuxmaster/QtDMM. Bug reports, meters that work or don't, and pull requests go there:

  • Issues — bugs, feature requests, protocol captures of unsupported meters
  • Pull requests — CI builds every change on Linux, macOS, FreeBSD and Windows and runs the test suite
  • Changelog — what changed between releases
  • Adding a protocol or a cable chip — decoder class, protocol table, test vectors under docs/protocols/spec/
  • Contact — for anything that does not fit into an issue
