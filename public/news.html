QtDMM 26.1-rc1: first release candidate

QtDMM 26.1-rc1 is out — the first release since 0.9.8 (2017). Downloads: a Windows installer and portable ZIP, and a Linux AppImage; for Fedora/Debian-based distributions, macOS and FreeBSD, build from source — see the download page.

It is a release candidate: please test and report problems on GitHub. Known issues in rc1, already fixed for rc2:

  • The AppImage ignores command-line options (--version, --config-id, ...)
  • On a 1080p Windows screen, the settings dialog is taller than the screen and its buttons are cut off (Enter/Esc still work)
  • No Bluetooth on macOS yet — the platform does not give programs the Bluetooth address of a device, which QtDMM needs to find Victron and UNI‑T meters
  • The UNI‑T UT61B+/D+/E+ and UT161 are implemented from the vendor's protocol tables but not yet confirmed on real hardware

The full list of changes is in CHANGELOG.

New version numbers: 26.1 instead of 1.0. QtDMM switches to calendar versioning (CalVer), the scheme used by many large projects such as Ubuntu, LibreOffice, pip and others. The format is YY.N: the year, then a running number for that year's releases — 26.1 is the first release of 2026, 26.2 would be the second, 27.1 the first of 2027. A bugfix release is 26.1.1, and release candidates carry a suffix, as in 26.1-rc1.

A calendar-based number tells you what you actually want to know: how current a version is, at a glance — and that a 0.9.7 copy is from another decade. It also means a release no longer waits on whether a change feels "big enough" for the next major number; a release happens when master is in good shape. The version comes straight from the git tag, and development builds show where they stand (26.2-dev.14 = 14 changes after 26.1). Details for packagers and contributors: Versions and releases in the developer documentation.

24 Sep 2026

QtDMM has a new home: github.com/qtdmm

QtDMM now lives in its own GitHub organization: github.com/qtdmm/QtDMM. tuxmaster, who carried the project since the Qt 5 port, transferred the repository there, so nothing was lost: history, releases, issues, stars and forks came along, and the old address github.com/tuxmaster/QtDMM redirects automatically. Existing clones keep working; to point yours at the new address:

git remote set-url origin https://github.com/qtdmm/QtDMM.git

The organization gives the project what a single account cannot: shared maintenance, roles, and a home that does not depend on one person. Together with this website it is the place for releases, bug reports, new meters and pull requests.

Thanks to tuxmaster for years of keeping QtDMM alive — and for handing it over so cleanly.
